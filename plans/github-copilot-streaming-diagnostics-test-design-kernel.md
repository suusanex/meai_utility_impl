## Manual-only checks

- [tests/MeAiUtility.MultiProvider.IntegrationTests/E2ETests/GitHubCopilotOptInE2ETests.cs](tests/MeAiUtility.MultiProvider.IntegrationTests/E2ETests/GitHubCopilotOptInE2ETests.cs) は既定無効のまま維持し、environment opt-in があるときだけ real Copilot path を実行することを確認する。
- RC-001 の disconnected、duplicate final、heartbeat、progress の sequence semantics は real SDK event を伴う確認が必要であり、通常 CI だけでは閉じない。
- RC-003 の long-running request で heartbeat または progress log が実際に無応答切り分けへ使えるかは、実 SDK と実 logger を使った opt-in 実行で確認する。
- partial output 後に SDK 例外が発生した場合、利用者にどこまで update を返してから failure とするかは product 判断を含むため、manual review 付き verification が必要である。

## Notes / assumptions

- RC-001 について、現行の [src/MeAiUtility.MultiProvider.GitHubCopilot/GitHubCopilotChatClient.cs](src/MeAiUtility.MultiProvider.GitHubCopilot/GitHubCopilotChatClient.cs) は GetResponseAsync 完了後に response.Text を空白分割して update を返しているため、TP-001 は現状の production code では NotImplementedOrMismatch になる前提で設計した。test design 上は delta 単位観測を要求するが、実装済みとは扱わない。
- RC-001 の timeout と cancellation は既存 code と test から unit で表現可能だが、disconnected、heartbeat、partial output 後 exception の completion semantics は [plans/github-copilot-streaming-diagnostics-runtime-contract-kernel.md](plans/github-copilot-streaming-diagnostics-runtime-contract-kernel.md) でも未固定であるため、TP-003 と TP-009 は to be determined を残した。
- RC-002 について、現時点の [src/MeAiUtility.MultiProvider.GitHubCopilot/Abstractions/ICopilotSdkWrapper.cs](src/MeAiUtility.MultiProvider.GitHubCopilot/Abstractions/ICopilotSdkWrapper.cs) は ListModelsAsync と final string を返す SendAsync だけを公開し、[tests/MeAiUtility.MultiProvider.GitHubCopilot.Tests/ConfigurationTests/GitHubCopilotServiceExtensionsTests.cs](tests/MeAiUtility.MultiProvider.GitHubCopilot.Tests/ConfigurationTests/GitHubCopilotServiceExtensionsTests.cs) でも DI 差し替えはこの契約だけに依存している。したがって additive な wrapper 拡張に対する安全な test point は、event surface、final aggregation の責務、DefaultCopilotSdkWrapper の代替 surface の 3 点が固定されるまで complete には書けない。
- 上記は RC-002 の non-breaking wrapper 拡張を否定する確定証拠ではないが、現状 evidence だけでは TP-005 を Done にできない。この 3 点のどれかを runtime contract だけで安全に固定できない場合は implementation-contract-kernel を追加し、interface realization を先に明文化する必要がある。
- RC-003 について、[src/MeAiUtility.MultiProvider/Telemetry/ChatTelemetry.cs](src/MeAiUtility.MultiProvider/Telemetry/ChatTelemetry.cs) は TraceId と RequestId の source of truth を持つ一方、現行の GitHub Copilot path では request start、response summary、CLI diagnostics、exception trace はあるが、major checkpoint log の full taxonomy は未接続である。したがって TP-007 は stage 設計を明示するが、current production での達成は前提にしない。
- secret masking は [tests/MeAiUtility.MultiProvider.GitHubCopilot.Tests/GitHubCopilotSdkWrapperTests.cs](tests/MeAiUtility.MultiProvider.GitHubCopilot.Tests/GitHubCopilotSdkWrapperTests.cs) の CLI diagnostics path masking と SDK trace translation から一部 evidence があるが、ProviderOverride 非機密のみ logging と prompt 非出力は GitHub Copilot path 全体では未充足であり、verification-kernel で production logger を確認する前提とする。
- 他 provider への副作用確認は user 指定参照範囲外の shared contract test を新規に読むと scope が広がるため、この pass では TP-006 に最小 binding requirement だけを書き、広い capability matrix 確認は downstream verification へ委譲する。
- integration-test-design または full-coverage への即時エスカレーションは推奨しない。selected contracts 単位の test point は定義できているためである。RC-002 の interface realization が unresolved の場合のみ implementation-contract-kernel へのエスカレーションを推奨する。
