# Runtime Contract Kernel

## Scope

本 artifact は plans/github-copilot-streaming-diagnostics-plan.md と plans/github-copilot-streaming-diagnostics-change-risk-triage.md を入力とし、selected contracts RC-001 / RC-002 / RC-003 のみを対象にした contract-kernel です。  
対象は GitHub Copilot SDK provider の streaming / diagnostics 強化に伴う runtime contract identification と participant / boundary mapping に限定し、実装・テスト設計・verification は含みません。  
ProviderOverride masking と capability advertisement は独立 contract としては扱わず、RC-003 と RC-002 の従属項目として扱います。

## Notes / assumptions

- RC-001: direct streaming method 名は未確定であり、runtime contract では CreateSessionAsync / On(Action<SessionLifecycleEvent>) / On(string, Action<SessionLifecycleEvent>) / SessionEvent / SessionEvent.FromJson / Rpc.SessionLogResult.EventId を公開 surface 候補としてのみ固定した。delta, heartbeat, disconnected, final の完全な sequence semantics は Status: PartiallyDone。
- RC-001: 現状の production path は session.SendAndWaitAsync で final text を返し、session.event は trace 翻訳基盤としてのみ観測されている。したがって「SDK event だけで final completion を閉じられるか」は未確定であり、verification-kernel ではなく test-design-kernel 以降の guardrail で観測点を割り当てる必要がある。Status: Deferred。
- RC-002: この pass では non-breaking wrapper 拡張を第一候補として固定した。理由は、現行 ICopilotSdkWrapper が ListModelsAsync / SendAsync の 2 面だけで DI と test substitute に広く使われており、GitHubCopilotServiceExtensions の DefaultCopilotSdkWrapper も同契約で fail-fast しているためである。Status: Done。
- RC-002: 次のいずれかが発生する場合は implementation-contract-kernel を推奨する。1) 追加契約だけでは GitHubCopilotChatClient の streaming path と non-streaming path の責務分離を書き切れない。2) DefaultCopilotSdkWrapper と既存 mock/stub wrapper が同一 interface で表現できない。3) final text aggregation を wrapper 側と chat client 側のどちらが担うかを runtime-contract-kernel だけで安全に固定できない。4) capability advertisement を non-breaking 追加契約だけでは決定できない。Status: PartiallyDone。
- RC-002: 上記条件に該当しない限り、implementation-contract-kernel は必須ではない。runtime-contract-kernel 時点の判断材料としては「既存 SendAsync を温存したまま event-driven 契約を別 surface で追加できるか」「production 実装と substitute 実装の双方がその surface を同じ DI 束縛で表現できるか」の 2 点を downstream で確認すれば足りる。Status: Done。
- RC-003: ChatTelemetry は TraceId / RequestId の source of truth として既に存在する一方、GitHubCopilotChatClient は現状 telemetry を開始しておらず、GitHubCopilotSdkWrapper のログも request start / response summary / CLI diagnostics / SDK trace translation に限られる。したがって diagnostics 強化は新規 stage 追加が必要であり、現状は full lifecycle correlation 未成立。Status: NotImplementedOrMismatch。
- RC-003: ProviderOverride masking は RC-003 の従属項目として扱う。BuildSdkSessionConfig では ApiKey / BearerToken / AzureApiVersion を SDK に渡すが、ログ契約として出してよいのは type / baseUrl / azureApiVersion などの非機密属性のみである。token / key / bearer / prompt 本文の扱いは Status: Done、stage ごとの一貫適用は Status: PartiallyDone。
- この slice は 3 contracts で十分に bounded であり、詳細 sequence 図がないと contract 表現自体が成立しない状態ではないため、runtime-evidence / full-coverage への即時エスカレーションは不要である。RC-002 の realization shape が未確定のときのみ implementation-contract-kernel を追加する。Status: Done。
